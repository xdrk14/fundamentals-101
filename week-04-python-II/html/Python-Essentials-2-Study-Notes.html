Day 1 · 3 hours

Modules, packages and pip

Vocabulary

WordMeaning
ModuleA single .py file that contains code (functions, variables, classes) you can reuse.
PackageA folder that groups several modules together.
ImportTo bring code from a module into your current file so you can use it.
LibraryA collection of modules and packages written by others (for example requests).
NamespaceThe "name area" that belongs to a module. math.pi means "the name pi inside math".
AliasA shorter nickname given to a module when importing it.
pipPython's installer program. It downloads libraries from the internet.
Standard libraryThe modules that come built into Python, such as math, csv and json. No installation needed.

1.1 What is a module?

Think of a module as a toolbox. Python ships with many ready-made toolboxes, such as math, random and datetime. You do not need to build these tools yourself; you simply open the toolbox.

Python
import math

print(math.sqrt(25))   # 5.0  -> square root
print(math.pi)         # 3.141592653589793

math.sqrt means "use the sqrt tool from the math toolbox". The dot (.) is how you reach inside something.

1.2 The three ways to import

StyleExampleHow you then use itWhen to use it
Whole moduleimport mathmath.sqrt(9)Default choice; clearest
Specific namesfrom math import sqrt, pisqrt(9)When you need only a few tools
With aliasimport math as mm.sqrt(9)When the module name is long

Avoid from math import * (imports everything). It fills your file with names you cannot see, which causes confusing clashes.

Added explanation: why clashes happen

If your own file has a variable called pi = 3 and you then run from math import *, Python silently replaces your pi with the one from math (or the other way round, depending on order). With import math, the two never collide, because one is pi and the other is math.pi. This separation is exactly what "namespace" means.

1.3 Writing your own module

Create two files in the same folder.

File 1: greetings.py (this is your module)

greetings.py
def say_hello(name):
    return f"Hello, {name}!"

COMPANY = "Best Tools Ltd"

File 2: main.py (this uses your module)

main.py
import greetings

print(greetings.say_hello("Anna"))   # Hello, Anna!
print(greetings.COMPANY)             # Best Tools Ltd

Note: you write import greetings, without .py.

Added explanation: three beginner traps with your own modules

  • Never name your file after an existing module. A file called math.py, json.py, csv.py or requests.py in your folder will be imported instead of the real one, and you will see strange errors such as module has no attribute. This is one of the most common beginner bugs.
  • File names must be valid Python names: letters, digits and underscores only, not starting with a digit. my_tools.py works; my tools.py and 2tools.py cannot be imported.
  • Importing runs the module's code once. Any print at the top level of greetings.py will run the moment main.py imports it. Section 1.4 shows how to prevent that.

You may also notice a new folder called __pycache__ appearing. Python stores a pre-processed copy of your module there to load it faster next time. It is safe to ignore or delete.

1.4 The if __name__ == "__main__": guard

Every module has a hidden variable called __name__.

How the file is usedValue of __name__
You run it directly (python greetings.py)"__main__"
Another file imports it"greetings" (its file name)

This lets you place test code that runs only when the file is run directly, not when imported:

greetings.py
def say_hello(name):
    return f"Hello, {name}!"

if __name__ == "__main__":
    print(say_hello("Test"))   # runs only when this file is run directly

Added explanation: "dunder" names

Names with double underscores on both sides, such as __name__, __init__ and __str__, are called dunder names. They are special names that Python itself uses. You will meet several more on Day 3. Read __name__ aloud as "dunder name".

1.5 Packages: folders of modules

Folder structure
my_project/
├── main.py
└── tools/
    ├── __init__.py        <- marks the folder as a package (may be empty)
    ├── maths_tools.py
    └── text_tools.py

tools/maths_tools.py

tools/maths_tools.py
def add(a, b):
    return a + b

main.py

main.py
from tools.maths_tools import add
from tools import text_tools

print(add(2, 3))   # 5

The dot (.) means "go inside". tools.maths_tools means "the maths_tools module inside the tools folder".

Added explanation: what __init__.py is for

An empty file named __init__.py tells Python "treat this folder as a package". Modern Python can often import a folder without it, but PE2 teaches it and it avoids surprises, so always include it. Any code you place inside __init__.py runs the first time the package is imported.

1.6 How Python finds modules

Python searches a list of folders stored in sys.path, starting with the folder of the file you are running. That is why your own modules must sit in the same folder (or in a package inside it).

Python
import sys
print(sys.path)

Useful helper: dir(math) lists every name inside a module, and help(math.sqrt) shows the documentation for one tool.

If Python cannot find a module, you will see ModuleNotFoundError: No module named '...'. Check three things: the spelling, whether the file is in the same folder, and (for outside libraries) whether you installed it with pip.

1.7 pip: installing outside libraries

Command (type in terminal, not in Python)Purpose
pip install requestsInstall a library
pip listShow installed libraries
pip show requestsDetails of one library
pip uninstall requestsRemove a library

On Windows, if pip is not recognised, use py -m pip install requests.

Added explanation: where pip gets libraries

pip downloads from PyPI (the Python Package Index, pypi.org), a public online store of free Python libraries. A common mistake is typing pip install requests inside the Python prompt (>>>); this produces a SyntaxError. pip commands belong in the terminal, not in Python itself.

Action

Install requests today; you will need it on Day 4.

Exceptions and debugging

Vocabulary

WordMeaning
ExceptionAn error that happens while the program is running (for example dividing by zero).
TracebackThe error report Python prints, showing where the error happened.
Handle / catchTo deal with an exception so the program does not crash.
RaiseTo deliberately create (trigger) an exception.
BugA mistake in code that causes wrong behaviour.
DebuggingThe process of finding and fixing bugs.
DebuggerA tool that pauses your program so you can inspect it line by line.
BreakpointA marker where the program pauses for inspection.

Added explanation: syntax errors versus exceptions

A syntax error is a grammar mistake (a missing colon, a bad bracket). Python refuses to start the program at all, and try/except cannot catch it; you must fix the code. An exception happens while a correctly written program is running, usually because of bad data (a user typing letters instead of a number, a missing file). Exceptions are what today is about.

2.1 Reading a traceback

Terminal output
Traceback (most recent call last):
  File "demo.py", line 2, in <module>
    print(10 / x)
ZeroDivisionError: division by zero

Read from the bottom up:

  1. Last line = the type of error (ZeroDivisionError) and the reason.
  2. Line above = the exact line of code and its line number.

<module> simply means "at the top level of the file, not inside a function".

2.2 Common exceptions

ExceptionCauseExample

TypeErrorWrong type"5" + 5
IndexErrorList position does not exist[1, 2][5]
KeyErrorDictionary key does not exist{"a": 1}["b"]

2.3 Basic try / except

Python
try:
    number = int(input("Enter a number: "))
    print(100 / number)
except ValueError:
    print("That was not a number.")
except ZeroDivisionError:
    print("You cannot divide by zero.")

How it works: Python tries the code. If an error occurs, it jumps to the matching except block instead of crashing.

Added explanation: what happens step by step

  • User types 5: both lines in try succeed, prints 20.0, and both except blocks are skipped.
  • User types abc: int("abc") fails. Python stops the try block immediately (the print line never runs) and jumps to except ValueError.
  • User types 0: the first line succeeds, the division fails, Python jumps to except ZeroDivisionError.

Keep the try block small: include only the lines that can actually fail. This makes it clear which line caused which problem.

2.4 The full structure

BlockWhen it runsTypical use
try:Always runs firstCode that might fail
except X:Only if error X happensHandle the problem
else:Only if no error happenedCode for the success case
finally:Always, error or notClean-up (closing files, messages)
Python
try:
    file = open("data.txt")
    content = file.read()
except FileNotFoundError:
    print("File not found.")
else:
    print("File read successfully.")
    file.close()
finally:
    print("Finished attempting to read the file.")

Added explanation: why else and finally both exist

else holds work that should only happen on success but that you do not want protected by the except (so a bug inside it is not mistakenly reported as "File not found"). finally is the guaranteed clean-up: it runs even if the except block itself fails or a function returns early. Think of finally as "switch off the lights on the way out, no matter what happened in the room".

2.5 Catching the error message

Python
try:
    int("abc")
except ValueError as error:
    print("Problem:", error)
    # Problem: invalid literal for int() with base 10: 'abc'

as error stores the exception in a variable so you can read its message. The name error is your choice; e and exc are also common.

2.6 The exception family tree

Exceptions are arranged like a family tree. A parent catches all its children.

Hierarchy
BaseException
 └── Exception
      ├── ArithmeticError
      │    └── ZeroDivisionError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      └── OSError
           └── FileNotFoundError

Rule

Put specific exceptions first, general ones last. Otherwise the general one catches everything and the specific block never runs.

Python
try:
    print(10 / 0)
except ZeroDivisionError:      # specific first
    print("Division by zero.")
except Exception:              # general last (safety net)
    print("Some other error.")

Avoid a bare except: with no name; it hides every problem, including ones you need to see.

Added explanation: catching several errors in one block

If two errors need the same response, group them in brackets: except (ValueError, TypeError):. Python checks the except blocks from top to bottom and runs only the first one that matches.

2.7 Raising your own errors

Python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative.")
    return age

try:
    set_age(-5)
except ValueError as error:
    print(error)   # Age cannot be negative.

Added explanation: why raise instead of print?

If set_age only printed a warning, the program would carry on with a wrong age. raise stops the function and forces whoever called it to deal with the problem. The function detects the problem; the caller decides what to do about it.

assert is a quick self-check used during development:

Python
x = 5
assert x > 0, "x must be positive"   # raises AssertionError if false

Use assert to check your own assumptions while writing code, not to validate user input; user input should be checked with if and raise.

2.8 Debugging with print

The simplest technique: print the values of variables at key points to see what is actually happening.

Python
def average(numbers):
    total = sum(numbers)
    print(f"DEBUG: {total=}, {len(numbers)=}")   # shows name and value
    return total / len(numbers)

average([4, 8, 12])
# DEBUG: total=24, len(numbers)=3

The {total=} form (Python 3.8+) prints both the variable name and its value. Remove debug prints when finished.

Added explanation: a method for print debugging

  1. Decide what value you expect at a given line.
  2. Print the actual value there.
  3. If they match, the bug is further down; if not, it is further up. Move the print and repeat.

Also print the type when confused: print(type(x)). Many bugs are a number stored as text, such as "25" instead of 25.

2.9 Debugging with pdb (the built-in debugger)

pdb = Python Debugger. Place breakpoint() where you want the program to pause:

Python
def average(numbers):
    breakpoint()                 # program pauses here
    total = sum(numbers)
    return total / len(numbers)

average([])

When paused, you see a (Pdb) prompt. Type commands:

CommandMeaning
p numbersPrint the value of a variable
nNext: run the current line, move to the next
sStep into a function call on the current line
cContinue running until the next breakpoint
lList: show the code around the current line
qQuit the debugger
hHelp

Example session:

Terminal
(Pdb) p numbers
[]
(Pdb) n
(Pdb) p total
0

You now see why the next line fails: dividing by len([]), which is 0.

Older equivalent: import pdb; pdb.set_trace().

Added explanation: using pdb comfortably

  • The line shown after the arrow (->) has not yet run. That is why total does not exist until you press n once.
  • Pressing Enter on an empty prompt repeats the last command, so you can press n once and then keep pressing Enter.
  • n versus s: n runs a function call in one go; s walks inside it. Use s only when you suspect the problem is inside that function.
  • Run pdb programs from a terminal (python file.py) for the most reliable experience. IDLE has its own separate tool under Debug → Debugger.
  • Remove every breakpoint() before sharing your program, or it will pause for other users too.

  1. Write a program that asks for two numbers and divides them, handling ValueError and ZeroDivisionError, with a finally message.
  2. Write a function get_item(my_list, index) that raises IndexError with a clear message.
  3. Put breakpoint() inside a loop and use p and n to watch a variable change.

Object-Oriented Programming (OOP)

Vocabulary

WordMeaning
ClassA blueprint (design plan) for creating objects.
Object / InstanceA real thing built from a class. "Instance" and "object" mean the same.
InstantiateTo create an object from a class ("make an instance").
AttributeA piece of data stored inside an object (a "property", such as name or age).
MethodA function that belongs to a class; something the object can do.
ConstructorThe special method __init__ that sets up a new object.
selfThe object's way of referring to itself.

3.1 The core idea

Real worldPython
Architect's house planClass
Actual houses built from the planObjects
Colour, number of roomsAttributes
Open door, switch on lightsMethods

One plan can produce many houses; each house has its own colour.

Added explanation: why OOP exists at all

Without classes, a student's data might live in separate variables: name1, grade1, name2, grade2, and so on, with loose functions that operate on them. This becomes messy quickly. A class packages the data and the actions that belong to that data into one unit. You have already been using objects without knowing: a string such as "hello" is an object of class str, and "hello".upper() calls one of its methods.

3.2 Your first class

Python
class Student:
    def __init__(self, name, grade):
        self.name = name        # attribute
        self.grade = grade      # attribute

# Creating objects (instances)
s1 = Student("Anna", 85)
s2 = Student("Ravi", 72)

print(s1.name)    # Anna
print(s2.grade)   # 72

Step by step:

  1. class Student: defines the blueprint. Class names use CapitalWords by convention.
  2. __init__ runs automatically whenever a new object is created. ("init" = initialise = set up.)
  3. Student("Anna", 85) creates an object; Python passes "Anna" to name and 85 to grade.
  4. self.name = name stores the value inside that particular object.

Added explanation: name versus self.name

These look alike but are two different things. name (the parameter) is a temporary variable that disappears when __init__ finishes. self.name is a permanent label attached to the object. The line self.name = name copies the temporary value into the permanent place. If you forget the self., the value is lost as soon as __init__ ends.

The simplest possible class uses the keyword pass, which means "nothing here yet": class Dog: pass. It is valid Python and you can already create objects from it with Dog().

3.3 Understanding self

When you write s1.name, Python looks inside object s1. Inside the class, the object does not yet have a variable name, so it calls itself self.

  • For s1, self is s1.
  • For s2, self is s2.

Rule

Every method's first parameter is self, but you never pass it yourself; Python passes it automatically.

Added explanation: what Python does behind the scenes

When you write s1.has_passed(), Python actually performs Student.has_passed(s1). The object before the dot becomes self. This is why forgetting self in a method definition causes the error TypeError: has_passed() takes 0 positional arguments but 1 was given: Python passed the object, but the method had no place to receive it.

3.4 Methods

Python
class Student:
    def __init__(self, name, grade):
        self.name = name
        self.grade = grade

    def has_passed(self):
        return self.grade >= 50

    def improve(self, points):
        self.grade += points

s1 = Student("Anna", 45)
print(s1.has_passed())   # False
s1.improve(10)
print(s1.grade)          # 55
print(s1.has_passed())   # True

Methods can read attributes (has_passed) and change them (improve).

Note: self.grade += points is short for self.grade = self.grade + points. Remember the brackets when calling a method: s1.has_passed() runs it, whereas s1.has_passed without brackets only refers to it.

3.5 Instance variables vs class variables

TypeWhere definedShared?Example
Instance variableInside methods with self.No; each object has its ownself.name
Class variableDirectly inside the classYes; shared by all objectsschool = "Royal"
Python
class Student:
    school = "Royal College"      # class variable (shared)
    count = 0                     # class variable (shared counter)

    def __init__(self, name):
        self.name = name          # instance variable (individual)
        Student.count += 1

a = Student("Anna")
b = Student("Ravi")
print(a.school, b.school)   # Royal College Royal College
print(Student.count)        # 2

Added explanation: why Student.count and not self.count?

To change the shared value, refer to it through the class name. Writing self.count += 1 would quietly create a new, separate count on that one object, and the shared counter would stay at 0. Reading through self is fine; changing a shared value should go through the class name.

3.6 Private attributes (encapsulation)

Two underscores in front of a name make it hidden from outside code (PE2 calls this private).

Python
class BankAccount:
    def __init__(self, owner):
        self.owner = owner
        self.__balance = 0          # private

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive.")
        self.__balance += amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Anna")
acc.deposit(100)
print(acc.get_balance())    # 100
# print(acc.__balance)      # AttributeError: hidden from outside

Outside code must use the methods, which can check that changes are valid. Note the raise from Day 2 protecting the data.

Added explanation: how "private" really works

Python does not lock the data away completely. It renames __balance to _BankAccount__balance behind the scenes (this is called name mangling), so the ordinary name no longer works from outside. It is a strong "do not touch" sign rather than a safe. A single underscore (_balance) is a gentler convention meaning "internal; please do not use from outside", with no renaming at all.

3.7 __str__: printing an object nicely

Python
class Student:
    def __init__(self, name, grade):
        self.name = name
        self.grade = grade

    def __str__(self):
        return f"Student {self.name} (grade {self.grade})"

print(Student("Anna", 85))   # Student Anna (grade 85)

Without __str__, printing shows something unreadable like <__main__.Student object at 0x...>. __str__ must return a string, not print one; print() calls it for you.

3.8 Inheritance

A child class (subclass) receives everything from a parent class (superclass), and can add or change behaviour.

Python
class Animal:                          # parent
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):                     # child: inherits from Animal
    def speak(self):                   # overriding (replacing) the parent method
        return f"{self.name} says Woof"

class Cat(Animal):
    def __init__(self, name, indoor):
        super().__init__(name)         # run the parent's __init__ first
        self.indoor = indoor

    def speak(self):
        return f"{self.name} says Meow"

print(Dog("Rex").speak())          # Rex says Woof
print(Cat("Kitty", True).indoor)   # True
TermMeaning
class Dog(Animal)Dog is a kind of Animal
OverrideReplacing a parent's method with a new version in the child
super()Refers to the parent class, so you can reuse its code

Added explanation: why Dog has no __init__ but Cat does

Dog needs only a name, which Animal.__init__ already handles, so Dog simply inherits it: Dog("Rex") uses the parent's constructor automatically. Cat needs an extra attribute (indoor), so it writes its own __init__. Doing so replaces the parent's version, which is why it must call super().__init__(name); otherwise self.name would never be set.

When Python looks for a method, it checks the object's own class first, then the parent, then the grandparent. The first match wins. That is how overriding works.

3.9 Useful built-in checks

FunctionPurposeExample result
isinstance(obj, Class)Is this object from that class (or its child)?isinstance(Dog("Rex"), Animal) → True
issubclass(A, B)Is class A a child of class B?issubclass(Dog, Animal) → True
hasattr(obj, "name")Does the object have this attribute?True
obj.__dict__Shows all the object's attributes{'name': 'Rex'}

Link to Day 2: custom exceptions are simply classes that inherit from Exception:

Python
class InsufficientFundsError(Exception):
    pass

Added explanation: using a custom exception

Because it inherits from Exception, it behaves like any built-in error. You raise and catch it the same way:

Python
try:
    raise InsufficientFundsError("Balance too low for this withdrawal.")
except InsufficientFundsError as error:
    print(error)   # Balance too low for this withdrawal.

Added explanation: where the file goes, and other ways to read

  • A plain name such as "notes.txt" is a relative path: the file is created in the folder the terminal was in when you ran the program (the "current working directory"), which may not be the folder of your .py file. If a file seems to vanish, check that folder, or run the program from inside its own folder.
  • file.write() does not add a new line automatically; you must include \n yourself.
  • Other ways to read: file.readline() reads one line; file.readlines() returns a list of lines; for line in file: reads line by line, which is best for large files.
  • A file object used in a with block is called a file handle: your program's grip on the open file.

4.2 CSV

A CSV file looks like this in a text editor:

people.csv
name,age,city
Anna,25,Colombo
Ravi,30,Kandy

Writing (list style):

Python
import csv

rows = [
    ["name", "age", "city"],
    ["Anna", 25, "Colombo"],
    ["Ravi", 30, "Kandy"],
]

with open("people.csv", "w", newline="", encoding="utf-8") as file:
    writer = csv.writer(file)
    writer.writerows(rows)      # writerow() for one row

newline="" prevents blank lines appearing between rows on Windows.

Reading (dictionary style, recommended):

Python
import csv

with open("people.csv", "r", newline="", encoding="utf-8") as file:
    reader = csv.DictReader(file)
    for row in reader:
        print(row["name"], row["age"])

DictReader uses the first line as column names, so each row becomes a dictionary.

Rule

Everything read from CSV is text. Convert when needed: int(row["age"]).

Writing with dictionaries:

Python
import csv

people = [{"name": "Anna", "age": 25}, {"name": "Ravi", "age": 30}]

with open("people2.csv", "w", newline="", encoding="utf-8") as file:
    writer = csv.DictWriter(file, fieldnames=["name", "age"])
    writer.writeheader()        # writes the header line
    writer.writerows(people)

Added explanation: why use the csv module instead of splitting on commas?

A value can itself contain a comma, for example the city "Colombo, Western Province". The csv module automatically wraps such values in quotation marks when writing and understands them when reading. Splitting lines yourself with line.split(",") would break that value into two columns. fieldnames tells DictWriter which dictionary keys to write and in what column order.

FunctionDirectionWorks with

Memory aid: the s stands for string.

Python
import json

person = {"name": "Anna", "age": 25, "skills": ["Python", "Excel"], "active": True}

# Save to file
with open("person.json", "w", encoding="utf-8") as file:
    json.dump(person, file, indent=4)     # indent makes it readable

# Load from file
with open("person.json", "r", encoding="utf-8") as file:
    data = json.load(file)

print(data["skills"][0])   # Python

Added explanation: JSON versus CSV, and strict JSON rules

  • CSV suits flat tables (rows and columns, as in Excel). JSON suits nested data, such as a person with a list of skills inside. Unlike CSV, JSON keeps numbers as numbers and true/false as booleans.
  • JSON is stricter than Python: strings and keys must use double quotes ("name", never 'name'), and a trailing comma after the last item is not allowed. Broken JSON raises json.JSONDecodeError when loading.
  • data["skills"][0] reads left to right: take the "skills" list from the dictionary, then its item at position 0.

4.4 Calling a public API with requests

The process mirrors typing an address into a browser, except your program receives the data.

Diagram
Your program  --- request (GET) --->  Web server
Your program  <--- response (JSON) ---  Web server

Status codes:

CodeMeaning
200OK: success
201Created
400Bad request (your request is wrong)
404Not found
500Server error (their side)

Rule of thumb

2xx = success, 4xx = your mistake, 5xx = server's problem.

First API call (JSONPlaceholder is a free practice API; no key needed):

Python
import requests

url = "https://jsonplaceholder.typicode.com/todos/1"
response = requests.get(url, timeout=10)

print(response.status_code)   # 200
data = response.json()        # converts JSON text to a Python dict
print(data["title"])
PartMeaning
requests.get(url)Send a GET request (ask for data)

response.status_codeThe status number

Added explanation: GET, POST, and what response.json() really does

  • GET means "give me data" (reading). POST means "here is new data, please store it" (sending). Today you only need GET.
  • The server sends back plain text in JSON format. response.json() is the same as json.loads(response.text): it turns that text into Python dictionaries and lists, so everything from section 4.3 applies.
  • Print the whole result once, print(data), to see which keys exist before picking one such as data["title"].
  • Many real APIs require an API key (a personal password for the service). JSONPlaceholder does not, which is why it is used for practice. Never share or publish your real API keys.

Safe version with exception handling (Day 2 applied):

Python
import requests

try:
    response = requests.get(
        "https://jsonplaceholder.typicode.com/users",
        timeout=10,
    )
    response.raise_for_status()          # raises an error for 4xx/5xx codes
    users = response.json()
except requests.exceptions.Timeout:
    print("The server took too long to respond.")
except requests.exceptions.RequestException as error:
    print("Request failed:", error)      # parent of all requests errors
else:
    for user in users:
        print(user["name"], "-", user["email"])

Added explanation: why raise_for_status() is needed

A 404 or 500 reply is not an exception by itself: the request technically succeeded in getting an answer, and the answer happened to be "not found". raise_for_status() converts any 4xx or 5xx code into a proper exception so your except block handles it. Note the order of the except blocks: Timeout (specific child) comes before RequestException (general parent), exactly as the Day 2 rule requires.

4.5 Final project: everything combined

Save as todo_app.py. It uses a class (Day 3), exceptions (Day 2), an API, JSON and CSV (Day 4), and can be imported as a module (Day 1).

todo_app.py
import csv
import json
import requests


class TodoFetcher:
    URL = "https://jsonplaceholder.typicode.com/todos"

    def __init__(self, limit=5):
        self.limit = limit
        self.todos = []

    def fetch(self):
        response = requests.get(self.URL, params={"_limit": self.limit}, timeout=10)
        response.raise_for_status()
        self.todos = response.json()

    def save_json(self, filename):
        with open(filename, "w", encoding="utf-8") as file:
            json.dump(self.todos, file, indent=4)

    def save_csv(self, filename):
        fields = ["userId", "id", "title", "completed"]
        with open(filename, "w", newline="", encoding="utf-8") as file:
            writer = csv.DictWriter(file, fieldnames=fields)
            writer.writeheader()
            writer.writerows(self.todos)


if __name__ == "__main__":
    fetcher = TodoFetcher(limit=5)
    try:
        fetcher.fetch()
        fetcher.save_json("todos.json")
        fetcher.save_csv("todos.csv")
    except requests.exceptions.RequestException as error:
        print("Could not download data:", error)
    except OSError as error:
        print("Could not save file:", error)
    else:
        print(f"Saved {len(fetcher.todos)} todos to JSON and CSV.")
    finally:
        print("Program finished.")
