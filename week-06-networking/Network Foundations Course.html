      M01

      Network fundamentals

      Name the parts of a network, the media that connect them, and the scale categories networks fall into.

      What a network is

      A network is two or more devices connected so they can exchange data. Every network has three kinds of component:

      • End devices (hosts): where data starts or finishes. PCs, phones, servers, printers, IP cameras.
      • Intermediary devices: move data between hosts. Switches, routers, wireless access points, firewalls.
      • Media: the path the signal travels. Copper cable, fibre-optic cable, or radio waves.

      Clients, servers and peer-to-peer

      A server is a host running software that provides information or a service: web pages, email, files. A client is a host running software that requests it, such as a browser or an email app. One computer can run several server roles at once.

      Client–server networkPeer-to-peer network

      AdvantagesCentral management, security and backup; scales wellEasy to set up, low cost, fine for simple tasks
      DisadvantagesCost of servers and administrationNo central administration, weak security, does not scale, slower
      ExampleAn office file server and email serverTwo home PCs sharing a printer

      Why models exist

      A layered model splits communication into jobs. Each layer serves the layer above it and relies on the layer below. Vendors can build one layer without caring how the others work, and troubleshooters can test one layer at a time.

      Encapsulation

      As data goes down the stack, each layer adds its own header (and Ethernet adds a trailer, the FCS checksum). The receiver strips them in reverse: de-encapsulation.

      L7 DataGET /index.html HTTP/1.1 …
      L4 SegmentTCP hdr · src 51544 dst 80Data
      L3 PacketIP hdr · 192.168.10.11 → 198.51.100.10TCP hdrData
      L2 FrameEth hdr · dst MAC of gatewayIPTCPDataFCS
      L1 Bits0110100101110011…

      Segmentation, multiplexing and sequencing

      Sending a large file as one continuous stream would block the network for everyone else and force a full resend after any error. Instead data is segmented into small pieces. Pieces from many conversations can then be interleaved on the same link: multiplexing. Each piece is sequenced so the receiver can rebuild the original in order, even if pieces arrive out of order or one has to be resent.

      Worked example · one web request through every layer
      1. L7: The browser builds GET / HTTP/1.1 for www.netlab.com. DNS has already resolved the name to 198.51.100.10.
      2. L4: TCP adds source port 51544 (random, ephemeral) and destination port 80, plus sequence numbers for reliability.
      3. L3: IP adds source 192.168.10.11 and destination 198.51.100.10. The host compares the destination with its own subnet, sees it is remote, and decides to send to its default gateway 192.168.10.1.
      4. L2: Ethernet needs the gateway's MAC address. ARP supplies it. The frame's destination MAC is the router's, while the IP destination stays the web server's.
      5. L1: The NIC turns the frame into electrical signals on the cable.
      6. At the router the frame is stripped, the packet is routed, and a new frame is built for the next link. IP addresses stay the same end to end (unless NAT rewrites them); MAC addresses change at every hop.
      Key ruleIP addresses identify the final source and destination. MAC addresses identify the current hop only.

      Physical layer and media

      Explain how bits become signals, compare copper, fibre and wireless media, and wire a UTP cable to standard.

      Purpose of the physical layer

      Layer 1 takes a complete frame from the data link layer and turns it into a stream of signals on the medium, and does the reverse at the receiver. Every NIC, cable, connector and radio belongs to this layer. A home router's Ethernet ports and Wi-Fi radio are both physical-layer connections.

      Characteristics

      Physical-layer standards come from ISO, EIA/TIA, ITU-T, ANSI and IEEE. They define three things:

      AreaMeaningExamples
      Physical componentsHardware: NICs, connectors, cable materialsRJ-45, LC fibre connector
      EncodingConverting bits into a recognisable codeManchester: every bit has a transition in the middle (in IEEE 802.3, a 0 is high-to-low and a 1 is low-to-high). NRZ: the level stays high or low for the whole bit
      SignallingHow 1 and 0 are represented on the mediumVoltage on copper, light pulses on fibre, modulated radio for wireless

      Bandwidth, throughput, goodput, latency

      TermDefinition
      BandwidthThe capacity of a medium: bits per second it can carry (bps, kbps, Mbps, Gbps, Tbps)
      ThroughputBits actually transferred per second; usually below bandwidth because of traffic, errors and device limits
      GoodputUsable data per second: throughput minus protocol overhead, retransmissions and handshakes
      LatencyDelay for data to travel from one point to another, including queuing

      A link is only as fast as its slowest segment: a 1 Gbps LAN behind a 100 Mbps internet service delivers at most 100 Mbps to the internet.

      Data link layer

      Explain the job of layer 2, its two sublayers, how devices share media, and how frames differ between LANs and WANs.

      Purpose

      The data link layer prepares network-layer packets for one specific medium and carries them across one link only. It:

      • lets upper layers use the medium without knowing whether it is copper, fibre or radio;
      • encapsulates the packet in a frame with layer 2 addresses;
      • controls when a device may place data on the medium;
      • detects damaged frames and discards them.
      SublayerStandardJob
      LLC (Logical Link Control)IEEE 802.2Talks to the network layer; identifies which protocol (IPv4, IPv6) is inside the frame
      MAC (Media Access Control)IEEE 802.3 Ethernet, 802.11 Wi-Fi, 802.15 BluetoothData encapsulation, addressing and media access in hardware

      At every router hop the frame is removed and a new one built for the next medium. A packet might travel inside an Ethernet frame on the LAN, a fibre WAN frame across the ISP and an 802.11 frame on the destination's Wi-Fi.

      Topologies

      The physical topology is how devices are cabled; the logical topology is how frames travel between them.

      Hub-and-spokeBranch sites connect through a central site; cheap but the hub is a single point of failure
      MeshEvery site links to every other; highly available but costly. Partial mesh is a compromise

      LAN topologies: star and extended star are standard today; bus (one shared cable) and ring (token passing) are legacy.

      Binary in one octet

      An IPv4 address is 32 bits written as four 8-bit octets in decimal: 192.168.10.11. Each octet holds 0–255. The eight bit positions are worth:

      Bit1286432168421
      Worked example · 172 to binary

      Subtract the largest place value that fits, left to right: 172 − 128 = 44 (1) · 64 does not fit (0) · 44 − 32 = 12 (1) · 16 does not fit (0) · 12 − 8 = 4 (1) · 4 − 4 = 0 (1) · 0 (0) · 0 (0). Result: 10101100.

      Back to decimal: add the place values of every 1. 128 + 32 + 8 + 4 = 172.

      Network and host portions

      Every address has a network portion (shared by all hosts on that subnet) and a host portion (unique per device). The subnet mask marks the split: 1 bits cover the network, 0 bits cover the host.

      Address   192.168.10.11   11000000.10101000.00001010.00001011
Mask      255.255.255.0   11111111.11111111.11111111.00000000
Network   192.168.10.0    ← AND of address and mask
Prefix    /24             ← count of 1 bits in the mask

      In every subnet two addresses are reserved: the network address (host bits all 0) and the broadcast address (host bits all 1). Usable hosts = 2h − 2, where h is the number of host bits.

      Subnetting and VLSM

      Find the network, broadcast, host range and mask of any address mentally, size subnets to requirements, and design a VLSM plan. Target: 40 drill answers correct in a row.

      Why subnet

      Splitting one large network into smaller ones shrinks broadcast domains, separates departments for security, and avoids wasting addresses. Subnetting borrows bits from the host portion and uses them as extra network bits.

      One large flat network means every broadcast (ARP, DHCP) reaches every host, wasting bandwidth and CPU. Segmenting by location (floor, building), by group (Sales, IT) or by device type (servers, printers, IP phones) shrinks those broadcast domains and lets ACLs control traffic between segments.

      FormulaMeaning
      2sNumber of subnets, where s = bits borrowed
      2h − 2Usable hosts per subnet, where h = remaining host bits
      256 − mask octetBlock size (the "magic number"): the gap between subnets in the interesting octet

      What the network layer does

      Layer 3 moves data between hosts on different networks through four operations: addressing end devices, encapsulation of segments into packets, routing (choosing the best path at each router), and de-encapsulation at the destination.

      IP characteristicMeaningConsequence
      ConnectionlessNo session is set up before sendingEach packet is handled independently and may take a different path
      Best effortNo guarantee of delivery, order or integrity of dataReliability is left to TCP or to the application
      Media independentWorks over copper, fibre, radio, any layer 2The MTU (maximum transmission unit, 1500 bytes on Ethernet) of each link limits packet size

      When an IPv4 packet is larger than the next link's MTU, a router may fragment it into smaller packets that are reassembled at the destination. Fragmentation adds delay and overhead. IPv6 routers never fragment; the sending host discovers the path MTU and sizes packets itself.

      MAC addresses

      A MAC address is a 48-bit layer 2 address burned into each network interface, written as 12 hex digits: 00-1A-2B-3C-4D-5E (Windows), 00:1a:2b:3c:4d:5e (Linux), or 001a.2b3c.4d5e (Cisco IOS).

      • First 24 bits: OUI, the manufacturer's identifier.
      • Last 24 bits: the interface's serial number assigned by that manufacturer.
      • FF:FF:FF:FF:FF:FF is the broadcast MAC. Addresses whose first octet is odd (lowest bit = 1) are multicast, such as 01:00:5E:… for IPv4 multicast.

      Modern phones and laptops often use a randomised MAC per Wi-Fi network for privacy.

      IPv6 addressing

      Read, compress and classify IPv6 addresses, explain how hosts configure themselves, and enable IPv6 on a Cisco router.

      Why IPv6

      IPv4's 32 bits allow about 4.3 billion addresses; the regional registries have exhausted their free pools. IPv6 uses 128 bits, about 3.4 × 1038 addresses, enough to give every device a public address and remove the need for NAT. It also drops broadcast entirely, using multicast instead.

      Address format and compression

      Eight groups (hextets) of four hex digits, separated by colons. Two rules shorten them:

      1. Remove leading zeros in any hextet: 0db8 → db8, 0000 → 0.
      2. Replace one run of two or more consecutive all-zero hextets with ::. Only once per address, otherwise the length is ambiguous. Compress the longest run; if two runs tie, compress the first. A single zero hextet is written as 0, not ::. Letters are written in lower case. These are the RFC 5952 rules, and the drill in M06 (IPv6 compression mode) checks against them.

      Reliability and windowing

      The receiver acknowledges the next byte it expects. If a segment is lost, the sender times out (or sees duplicate ACKs) and resends. The window size tells the sender how many bytes it may send before waiting for an acknowledgement; the receiver shrinks it when it is overloaded. Wireshark marks problems as TCP Retransmission, Dup ACK and Zero Window.

      Maximum segment size, selective acknowledgement and congestion

      • MSS: the largest data block a host will accept in one segment, announced during the handshake. On Ethernet it is typically 1460 bytes (1500 MTU minus 20 bytes IPv4 and 20 bytes TCP header).
      • SACK (selective acknowledgement), negotiated in the handshake, lets the receiver report exactly which byte ranges arrived, so only the missing segments are resent rather than everything after the gap.
      • Congestion avoidance: when segments are lost or delayed, the sender assumes the network is congested and reduces how much it sends before waiting for acknowledgements, then increases again gradually.

      UDP communication

      UDP sends each datagram independently. Datagrams may arrive out of order or not at all, and UDP does nothing about it; the application decides whether to ignore loss (voice), ask again (DNS resolvers retry after a timeout) or reorder using its own sequence numbers (RTP for media). A UDP server listens on its well-known port (DNS on 53, DHCP on 67); clients use random source ports, exactly as with TCP.

      • Wi-Fi uses CSMA/CA (collision avoidance): a station listens, waits a random back-off, then transmits, and every unicast frame is acknowledged. Wired Ethernet historically used CSMA/CD (collision detection).
      • A client scans (passively via beacons, or actively via probe requests), authenticates, then associates with the access point.
      • Larger sites use lightweight access points managed by a wireless LAN controller (WLC).

      Network security and troubleshooting

      Follow a structured method to isolate faults, use the standard diagnostic commands, and harden devices against common threats.

      Structured troubleshooting

      1. Identify the problem: who is affected, what exactly fails, when it started, what changed.
      2. Establish a theory of probable cause.
      3. Test the theory; if wrong, form a new one.
      4. Plan and implement the fix.
      5. Verify full functionality, including that nothing else broke.
      6. Document findings, actions and outcome.

      Bottom-up (L1 → L7)Suspected physical problem, or many users affected

      Swap componentsReplace a cable or port to rule it out quickly

      Threats and vulnerabilities

      A threat is something that could cause harm; a vulnerability is a weakness it exploits. Successful attacks result in information theft, data loss or manipulation, identity theft, or disruption of service.

      Vulnerability typeExamples
      TechnologicalWeaknesses in TCP/IP protocols (HTTP, SNMP, SMTP sending in plain text), operating systems and network equipment
      ConfigurationUnsecured user accounts, easily guessed or default passwords, misconfigured services, unpatched devices
      Security policyNo written policy, no disaster-recovery plan, changes made without control, policy not enforced

      Physical threats matter as much: hardware (theft, vandalism), environmental (heat, humidity), electrical (spikes, brownouts) and maintenance (poor handling, no spares). Lock network rooms and use UPS power.

      Build and troubleshoot a small network

      Choose devices for a small office, plan its addressing and traffic, prepare it to grow, and fix the five classic faults.

      Devices in a small network

      A typical small network has one router (internet edge, often with a firewall), one or more switches, a wireless access point, a few servers or printers, and perhaps IP phones. Select devices against four factors:

      FactorQuestions to ask
      CostPurchase price, number and speed of ports, management features, cabling, support contracts
      Speed and port typesFast Ethernet, Gigabit or 10 Gbps; copper or fibre uplinks; PoE for phones and access points
      ExpandabilityFixed-configuration devices cannot be extended; modular devices accept extra interface cards
      Operating system featuresSecurity, QoS, VoIP, NAT and DHCP support; licensing

      Addressing: apply a structured plan (M06 Example 7) so servers, printers, network devices and user pools sit in predictable ranges. Redundancy: duplicate the components whose failure would stop the business, such as a second internet link or a spare switch. Traffic management: give real-time traffic priority with QoS, typically voice first, then video, then interactive data, then bulk transfers.

      Applications and protocols

      Distinguish network-aware applications (browsers, email clients that talk to the network themselves) from application-layer services (file transfer, print spooling, which applications call on). A small business typically relies on DNS, DHCP, HTTP/HTTPS, SMTP/IMAP, SMB file sharing and SSH for management. Real-time applications add requirements: VoIP and IP telephony need low delay and QoS on every device in the path, and video uses RTP (Real-time Transport Protocol) over UDP with RTCP for quality feedback.
