Variables and Data Types

A variable in Python is a name bound to an object. Unlike languages where a variable is a fixed memory box, Python names are references — the same object can have several names, and a name can be rebound to a different type at any time.

Assignment and dynamic typing

Python infers type from the assigned value at runtime. No type declaration is required or possible in the C/Java sense.

age = 25              # int
price = 19.99          # float
name = "Bimal"         # str
is_active = True       # bool
nothing = None         # NoneType

age = "twenty-five"    # legal — age now refers to a str

Core built-in types

TypeExampleMutableNotes
int42, -7NoArbitrary precision — no overflow
float3.14NoIEEE-754 double; subject to rounding error
complex2+3jNoRare at PE1 level; real/imaginary parts
str"text"NoSequence of Unicode characters
boolTrue, FalseNoSubtype of int: True == 1
NoneTypeNone—Represents "no value"
FLOAT PRECISION 0.1 + 0.2 evaluates to 0.30000000000000004, not 0.3 — a binary floating-point limitation, not a Python bug. Compare floats with tolerance, not ==.

Numeral systems

Python accepts binary, octal, and hexadecimal integer literals, all stored internally as the same int type.

binary_lit = 0b1010     # 10
octal_lit  = 0o12        # 10
hex_lit    = 0xA          # 10

bin(10)      # '0b1010'
oct(10)       # '0o12'
hex(10)        # '0xa'
int("2A", 16)   # 42 — parse a string in a given base

Type checking and conversion

type(age)          # <class 'int'>
isinstance(age, int)  # True

str(25)          # "25"
int("42")         # 42
int("3.9")          # ValueError — int() won't parse a float string
float(int("3"))       # 3.0
bool(0)                # False
bool("")                 # False
bool("0")                  # True — non-empty string is always truthy

Naming rules

  • Letters, digits, underscores only; cannot start with a digit.
  • Case-sensitive: age and Age are different names.
  • Cannot be a reserved keyword (if, for, class, return, …).
  • Convention: snake_case for variables and functions, PascalCase for classes, UPPER_SNAKE for constants.

Multiple and augmented assignment

a, b = 1, 2          # tuple unpacking assignment
a, b = b, a              # swap without a temp variable

x = y = z = 0               # chained assignment — all bind to the same object

count = 0
count += 1     # count = count + 1
count *= 3      # count = count * 3

Operator precedence (arithmetic)

Highest to lowest binding: () → ** → unary + - ~ → * / // % → + -. Exponentiation is right-associative: 2 ** 3 ** 2 is 2 ** (3 ** 2) = 512.

10 // 3    # 3  — floor (integer) division
10 % 3      # 1  — modulo/remainder
2 ** 10      # 1024 — exponentiation
-3 ** 2       # -9 — unary minus binds looser than **

Literals

A literal is data written directly into source code, as opposed to a value computed at runtime. 25, 3.14, "hi", and True are all literals.

The print() function

print("Hello, World!")

print("a", "b", "c")                    # multiple positional arguments
print("a", "b", "c", sep="-")             # "a-b-c" — custom separator
print("Loading", end="...")                 # "end" replaces the default trailing newline
print("done")                                  # continues on same line as above

print("Tab:\tNewline:\nDone")                     # escape characters inside a string

sep and end are keyword arguments with defaults " " and "\n" respectively — this is the canonical example PE1 uses to introduce positional vs. keyword arguments before functions are formally covered.

Conditionals

Conditional execution branches program flow based on boolean expressions. Python uses indentation — not braces — to define blocks, making consistent whitespace a syntax requirement, not a style preference.

if / elif / else

score = 78

if score >= 90:
    grade = "A"
elif score >= 75:
    grade = "B"
elif score >= 60:
    grade = "C"
else:
    grade = "F"

print(grade)   # B

Only one branch executes. elif chains are evaluated top to bottom; the first true condition wins and the rest are skipped.

Comparison and logical operators

and/or short-circuit: in a() or b(), b() only runs if a() is falsy. This is often used for default values: name = input_name or "Guest".

Truthy and falsy values

Every object has an implicit boolean value when used in a condition. Falsy: 0, 0.0, "", [], {}, (), set(), None, False. Everything else — including any non-empty string, list, or nonzero number — is truthy.

name = ""
if not name:
    print("Name is empty")

items = []

    print("Has items")

Chained comparisons

if 0 < score < 100:      # equivalent to: 0 < score and score < 100
    print("Valid score")

Conditional (ternary) expression

COMMON PITFALL = is assignment, == is comparison. if x = 5: is a SyntaxError in Python — unlike C, Python does not allow assignment inside a condition by accident, which prevents a classic bug class.

Bitwise operators

Bitwise operators act on the binary representation of integers, bit by bit — distinct from the logical and/or/not, which act on whole truth values.

Loops

Python provides two loop constructs: for, which iterates over any iterable, and while, which repeats while a condition holds. Both support break, continue, and an unusual else clause.

for loop

for i in range(5):        # 0, 1, 2, 3, 4
    print(i)

fruits = ["apple", "mango", "kiwi"]
for fruit in fruits:
    print(fruit)

for i, fruit in enumerate(fruits):      # index + value together
    print(i, fruit)

names = ["Bimal", "Nathaliya"]
ages = [53, 20]
for name, age in zip(names, ages):        # parallel iteration
    print(name, age)

range() signature

CallProduces
range(5)0, 1, 2, 3, 4
range(2, 8)2, 3, 4, 5, 6, 7
range(2, 10, 2)2, 4, 6, 8
range(10, 0, -2)10, 8, 6, 4, 2

range() is lazy — it produces values on demand rather than building a full list in memory, which matters for large ranges.

while loop

count = 0
while count < 5:
    print(count)
    count += 1

# deliberate infinite loop, exited via break
while True:
    response = input("Continue? (y/n): ")
    if response == "n":
        break

break, continue, and the loop else

for i in range(10):
    if i == 3:
        continue       # skip rest of this iteration, go to next
    if i == 7:
        break            # exit the loop immediately
    print(i)
else:
    print("Completed without break")   # runs only if loop finished naturally

# practical use: search with a "not found" fallback
target = 11
for n in [2, 4, 6, 8]:
    if n == target:
        print("Found")
        break
else:
    print("Not found")    # this runs — loop never broke

Nested loops

for row in range(3):

COMMON PITFALL Never remove items from a list while iterating over it directly — indices shift and items get skipped. Iterate over a copy (for x in list[:]:) or build a new list instead.

Functions, Parameters, Return Values

Functions package reusable logic behind a name. Python functions are first-class objects — they can be passed around, stored in collections, and returned from other functions.

Defining and calling

def greet(name):
    """Return a friendly greeting for the given name."""
    return f"Hello, {name}!"

result = greet("Bimzy")
print(greet.__doc__)   # prints the docstring

Default and keyword arguments

def power(base, exponent=2):
    return base ** exponent

power(5)          # 25   — uses default exponent
power(5, 3)        # 125

def describe(name, age, city):
    return f"{name}, {age}, {city}"

describe(age=30, name="Nathaliya", city="Colombo")   # order doesn't matter with keywords

Variable-length arguments

def total(*args):               # collects extra positional args into a tuple
    return sum(args)

def config(**kwargs):             # collects extra keyword args into a dict
    return kwargs

total(1, 2, 3)                       # 6
config(host="local", port=8080)        # {'host': 'local', 'port': 8080}

def report(title, *values, **meta):     # combining all forms
    print(title, values, meta)

report("Sales", 100, 200, region="APAC")

Positional-only and keyword-only parameters

The / and * markers in a signature restrict how arguments may be passed — useful for API clarity.

def move(x, y, /, *, speed=1):
    # x, y: positional-only (before /)
    # speed: keyword-only (after *)
    return (x + speed, y + speed)

move(3, 4, speed=2)     # OK
move(x=3, y=4)              # TypeError — x, y are positional-only

Return values

def divide(a, b):
    if b == 0:
        return None        # explicit "no result"
    return a / b

def min_max(numbers):
    return min(numbers), max(numbers)   # returns a tuple

low, high = min_max([4, 1, 9, 2])         # unpacked directly

A function with no explicit return statement returns None implicitly.

Scope: local, global, nonlocal

counter = 0

def increment():
    global counter        # without this, counter += 1 raises UnboundLocalError
    counter += 1

def outer():
    total = 0
    def inner():
        nonlocal total     # modifies the enclosing function's variable
        total += 1
    inner()
    return total

Python resolves names using the LEGB rule: Local → Enclosing → Global → Built-in, searched in that order.

Functions as first-class objects

def square(x):
    return x * x

funcs = [square, abs, str]      # stored in a list like any value
[f(-4) for f in [square, abs]]     # [16, 4]

def apply_twice(f, x):
    return f(f(x))

apply_twice(square, 3)        # 81

Lambda functions

square = lambda x: x ** 2
add = lambda a, b: a + b

Recursion

def factorial(n):
    if n <= 1:            # base case — stops the recursion
        return 1
    return n * factorial(n - 1)   # recursive case

factorial(5)   # 120

MUTABILITY AND ALIASING b = a for a list does not copy it — both names point to the same object, so mutating b mutates a too. Use b = a.copy() or b = a[:] for a shallow copy, or copy.deepcopy(a) for nested structures.

Functions vs. methods

PE1 draws a deliberate distinction: len(nums) is a function — it takes the list as an argument. nums.append(9) is a method — it's called on the list object itself via dot notation. Both are common, but they aren't interchangeable: there's no nums.len(), and no append(nums, 9).

The in / not in operators

nums = [3, 1, 4, 1, 5]

4 in nums          # True — membership test
9 not in nums         # True — 9 isn't in the list

Sorting: the bubble sort algorithm

PE1 introduces sorting through bubble sort specifically — not because it's efficient (it isn't; O(n²)), but because it's simple enough to build by hand and illustrates how an algorithm is constructed from loops and conditionals.

def bubble_sort(data):
    n = len(data)
    for i in range(n - 1):                  # outer pass
        for j in range(n - 1 - i):            # inner comparison
            if data[j] > data[j + 1]:
                data[j], data[j + 1] = data[j + 1], data[j]   # swap
    return data

bubble_sort([5, 2, 9, 1, 5, 6])   # [1, 2, 5, 5, 6, 9]

Each full pass "bubbles" the largest remaining unsorted value to its correct position at the end of the list. Python's built-in .sort() uses a far more efficient algorithm (Timsort) — bubble sort here is a teaching exercise in algorithmic thinking, not a recommended production tool.

Basic File I/O

Python reads and writes files through file objects opened with open(). The with statement is the standard idiom — it guarantees the file is closed even if an error occurs mid-operation.

File modes

ModeMeaning
"r"Read (default); errors if file doesn't exist
"w"Write; creates file, overwrites if it exists
"a"Append; creates file if missing, adds to the end
"x"Exclusive create; errors if file already exists
"r+"Read and write, file must exist
"rb" / "wb"Binary variants — append b for non-text files

Writing

with open("notes.txt", "w") as f:
    f.write("First line\n")
    f.write("Second line\n")

lines = ["one\n", "two\n", "three\n"]
with open("notes.txt", "w") as f:
    f.writelines(lines)          # expects newlines already included

Reading

with open("notes.txt", "r") as f:
    content = f.read()          # entire file as one string

with open("notes.txt", "r") as f:
    first_line = f.readline()      # one line, including \n

with open("notes.txt", "r") as f:
    all_lines = f.readlines()         # list of lines

with open("notes.txt", "r") as f:            # memory-efficient — one line at a time
    for line in f:
        print(line.strip())

Appending

with open("notes.txt", "a") as f:
    f.write("Third line\n")

Why with matters

# without with — must remember to close, and close is skipped on error
f = open("notes.txt", "r")
content = f.read()
f.close()

# with — file closes automatically, even if an exception is raised inside the block
with open("notes.txt", "r") as f:
    content = f.read()
# f is guaranteed closed here

Handling a missing file

try:
    with open("missing.txt", "r") as f:
        data = f.read()
except FileNotFoundError:
    print("File does not exist")

This pattern connects directly to the next topic — exceptions are the standard way Python signals and handles I/O failures.

Working with paths

import os

os.getcwd()                        # current working directory
os.path.exists("notes.txt")           # True/False — check before opening
os.path.join("data", "notes.txt")        # "data/notes.txt" — builds paths portably across OSes

from pathlib import Path              # modern alternative to os.path
p = Path("data") / "notes.txt"
p.exists()
p.read_text()                              # reads whole file as a string, no "with" needed
p.write_text("Hello\n")                       # writes, creating the file if missing

Relative paths ("notes.txt") are resolved against the current working directory, which is wherever the script was launched from — not necessarily the script's own folder. This trips up beginners more than any other file-handling issue: a script that works when run from one folder can raise FileNotFoundError when run from another.

An Introduction to Exceptions

Exceptions are Python's mechanism for signaling and responding to errors at runtime, separating normal program logic from error-handling logic.

try / except / else / finally

try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
except (TypeError, ValueError) as e:     # catch multiple types, capture the exception object
    print(f"Error: {e}")
else:
    print("No exception occurred")            # runs only if try succeeded
finally:
    print("Always runs")                          # runs no matter what — success, failure, or return

finally is typically used for cleanup — closing a connection or file — that must happen regardless of outcome.

Exception hierarchy

All built-in exceptions descend from BaseException. Catching Exception (not BaseException) is the usual practice — it excludes system-exit signals like KeyboardInterrupt that generally shouldn't be silently swallowed.

BaseException
 └── Exception
      ├── ArithmeticError
      │     └── ZeroDivisionError
      ├── LookupError
      │     ├── IndexError
      │     └── KeyError

      ├── TypeError
      └── OSError
            └── FileNotFoundError

Raising exceptions

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

try:
    set_age(-5)
except ValueError as e:
    print(e)     # "Age cannot be negative"

Custom exceptions

class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the available balance."""
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Cannot withdraw {amount}, balance is {balance}")
    return balance - amount

try:
    withdraw(100, 150)
except InsufficientFundsError as e:
    print(e)

assert for internal checks

def average(numbers):
    assert len(numbers) > 0, "List cannot be empty"
    return sum(numbers) / len(numbers)

assert raises AssertionError if the condition is false. It's intended for catching programmer errors during development — not for validating untrusted user input, since assertions can be globally disabled at runtime with the -O flag.

Bare except and why to avoid it

try:
    risky_operation()
except:                    # catches literally everything, including KeyboardInterrupt
    print("Something went wrong")

# better — catch what you actually expect, and keep the rest visible
try:
    risky_operation()
except (ValueError, TypeError) as e:
    print(f"Something went wrong: {e}")

A bare except: silences real bugs along with expected failures, making problems harder to find. PE1 flags this explicitly as something to avoid.

Debugging and testing

PE1 closes on the practical reality that untested code cannot be trusted. Two techniques it introduces at this level:

  • Print debugging — inserting temporary print() calls to inspect variable state at specific points while tracking down a bug.
  • Unit testing — writing small, automated test functions that verify a piece of code behaves correctly, so regressions are caught automatically rather than by manual re-checking.
def add(a, b):
    print(f"DEBUG: a={a}, b={b}")   # print debugging — removed once the bug is found
    return a + b

# a minimal unit test, in the spirit of PE1's introduction to the concept
def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    print("All tests passed")
